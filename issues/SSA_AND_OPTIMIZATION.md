# 架构演进建议：引入 SSA 中间表示与高级编译优化

## 1. 背景与现状
目前的 **致爱 (Zhiai)** 编程语言采用了经典的“栈式虚拟机 (Stack-based VM)”架构。
- **优点**：指令集简单，编译器实现直观，跨平台移植性强。
- **现状**：JIT 与 AOT 编译器目前主要通过对字节码的“直译”生成 Python 代码。由于缺乏对控制流和数据流的深度分析，生成的代码包含大量冗余的栈操作（PUSH/POP），且难以进行系统性的自动优化。

## 2. 核心建议：升级 IR 为 SSA 形式
**SSA (Static Single Assignment, 静态单赋值)** 是现代高性能编译器（如 LLVM, V8, Go）的核心中间表示形式。

### 2.1 什么是 SSA？
在 SSA 形式中，每个变量有且仅有一个赋值语句。
- **原始代码**：
  ```zhiai
  让 a = 1
  a = a + 2
  输出(a)
  ```
- **SSA 形式**：
  ```text
  a1 = 1
  a2 = a1 + 2
  PRINT(a2)
  ```

### 2.2 引入 SSA 的收益
1. **死代码消除 (Dead Code Elimination)**：自动识别并剔除从未被使用的变量赋值。
2. **常量传播 (Constant Propagation)**：在编译期计算出已知数值的结果，减少运行时负担。
3. **全局值编号 (GVN)**：识别并消除重复的子表达式计算。
4. **为原生 AOT 铺路**：SSA 是对接 LLVM 或生成高效机器码的工业标准。

## 3. 演进路线图 (Roadmap)

### 阶段一：三地址码化 (3-Address Code) - 预计 v1.1.x
- **任务**：将栈式指令转换为线性寄存器指令。
- **目标**：消除 JIT 生成代码中 50% 以上的临时 PUSH/POP 开销。

### 阶段二：控制流图构建 (CFG Construction) - 预计 v1.2.x
- **任务**：分析 `如果`、`循环`、`尝试` 构成的基本块 (Basic Blocks) 及其跳转关系。
- **价值**：这是进行跨块优化的前提。

### 阶段三：正式 SSA 与 Phi 函数 - 预计 v1.5.x
- **任务**：引入 $\phi$ 函数处理分支汇合点，实现完整的 SSA。
- **目标**：实现“工业级”的代码优化能力。
